# R8: "Làm thêm" and the break bank (design)

- **Date:** 08–09/11/2026. Parent decisions were made through popups on the evening of 08/11.
- **Trigger:** Nguyên studied Math OS / English OS twice today, once for 1 h and once for 30'. Under today's rules:
  - A supplementary or skill task is done after one run of ≥ 20'. After that, the start route answers "Việc này đã xong rồi", so further study is not recorded.
  - She gets only one 10' break per day, and only after a whole part is done.
  - She wants a break after about every hour of focus, and the break should open the web.
- **This changes the lock / open rules** (DESIGN §5, `lib/dayState.ts`). The parent asked for it explicitly. The rules and gold examples below were confirmed by the parent and are the source of truth.

  - **R8a "Làm thêm"** needs no SQL.
  - **R8b "Ngân hàng giờ nghỉ"** needs SQL migration `0014`. It is built on R8a, so its PR contains R8a until R8a is merged. Merge R8a first.

## R8a — "Làm thêm" (more sessions of a done task)

### Rules

1. **Starting again.** A **template** task (bài bổ sung or kỹ năng) that is done today can be started again with **"Làm thêm"**. This creates a new `task_runs` row for the same template and today's `local_date`; the table already allows several runs per template per day.
2. **Homework is unchanged.** It finishes with a photo or parent proof, and there is no "Làm thêm".
3. **An extra run never changes completion.**
   - The task stays done; the part milestones and free time are untouched.
   - An extra run has **no minimum**: "Xong" is allowed at any time.
   - It is never required, and it never re-locks anything.
4. **One timed task at a time** still holds:
   - An extra run counts as timed for the "one running at a time" rule.
   - The existing break rule "no timed task running" also applies to extra runs.
5. **Totals.**
   - `TaskView` gains `todayMinutes`: the sum of all of today's run durations for that template, using the server clock, with a running run counting up to now, floored to minutes.
   - It also gains `sessions`: the number of today's runs with `started_at`.
   - It gains `extra: { runId, startedAt } | null` while an extra run is running.
   - The first, required run keeps its existing fields.
6. **Old data:**
   - An unfinished extra run from an earlier day is ignored, as rule 11 says.
   - For a template marked done today, the "done" run is the earliest run with `done_at`. Every later run is an extra run.
7. **Routes:**
   - `/api/tasks/start` on a done template starts an extra run. A second click while one is running returns the running one (idempotent).
   - `/api/tasks/finish` with an extra `runId` sets `done_at` with no minimum check.
   - The validation stays server-side.

### UI

- On a done template row and card ("✓ Xong"), add the sub-line **"Hôm nay: 1 giờ 30 phút · 2 lần"**. Use the same `minutesLabel` style as the timers; show minutes only, never seconds.
- Add a button **"Làm thêm"**. It opens the R7a start sheet, with the title "Làm thêm: {title}" and the hint "Không bắt buộc — làm bao lâu cũng được".
- **While an extra run is running:**
  - the running chip and the focus view work as usual;
  - the timer counts up with no minimum and no ring progress (a gentle breathing ring, as for homework);
  - "Xong" is enabled at once.
- **Hôm nay cards** (R6d) keep their meaning.
  - The Kỹ năng and Học tập progress stays based on the required work.
  - An extra session may show "đang làm thêm" on the row.
- **No counters or praise for "Làm thêm"**: no "+1", no ranking, no streak.

### Tests

- **Vitest (`tests/dayState.test.ts` plus `lib/today/rules` tests):**
  - done plus extra running: still done, parts unchanged, `todayMinutes` sums;
  - the earliest done run is the required one;
  - an extra run from yesterday is ignored;
  - a second start while one is running is idempotent;
  - finishing an extra run has no minimum;
  - start is denied for a homework item that is done.
- **e2e (`e2e/r8a.spec.ts`, self-contained):**
  - seed a template finished today (a 25' run);
  - "Làm thêm" starts a run;
  - the chip shows it;
  - "Xong" right away works;
  - the row shows "Hôm nay: … · 2 lần";
  - the part stays done;
  - restore everything in `finally`.

## R8b — Ngân hàng giờ nghỉ (the break bank)

### Definitions

- **Focus time:** the minutes during which **at least one** of today's **finished** task runs was running, by the server clock. Homework, template and extra runs all count, and overlapping runs are counted **once** (union of intervals).
  - **Parent decision 09/11 (after an independent review found a loophole):** a run adds focus **only once it has `done_at`**: Xong for a template or an extra run; the photo or the parent's confirmation for homework. A running or forgotten run adds **0** until it is finished.
  - A run's interval is `[started_at, min(done_at, started_at + 180')]`, clipped to today (00:00–24:00 VN). The cap is data: `family_settings.break_run_cap_minutes` (default 180, 30–600).
  - Finishing a run later may add earnings, after the fact, to the block(s) its interval falls in. The bank stays the sum of block earnings minus the minutes used, computed from the data only.
  - **Not focus:**
    - time inside a break;
    - time after `free_started_at`;
    - time under OPEN_TRUST / OPEN_SICK / a parent OPEN override (the laptop is open anyway).
  - Time under a parent LOCK override **does** count, because the child is studying.
- **Block:** focus time since the start of the most recent break, or since the start of the day if there has been no break yet. **Starting a break closes the block**; after a break, counting starts again from zero.
- **Tiers:** stored as data in `family_settings.break_tiers`, a JSON array of `[focusMinutes, breakMinutes]`, ascending. The default is `[[45,10],[90,30],[120,45],[180,60]]`.
  - `earn(F)` = the break minutes of the highest tier with `focusMinutes ≤ F`, or 0.
  - If `F` is at least the top tier (180), add `earn(F − 180)` recursively, counting the rest as a new block.
  - Examples: 44 → 0 · 45 → 10 · 89 → 10 · 90 → 30 · 119 → 30 · 120 → 45 · 179 → 45 · 180 → 60 · 224 → 60 · 225 → 70 · 270 → 90 · 360 → 120.
- **A break's real end** = min(`ended_at`, `started_at + planned`, free start, 00:00, the `created_at` of the first parent LOCK override created after the break started). **Parent decision 09/11:** a parent lock during a break ends it then and gives the unused minutes back to the bank; the break does not resume after the lock.
- **Bank** (break minutes available now):
  - `earn(current block)`
  - plus the earnings of every earlier, closed block
  - minus the minutes **actually used** in every break so far.
  - A break used early by "Học tiếp" (or cut by a parent lock) counts only the minutes used, floor((real end − start) ÷ 1'); the rest stays in the bank.
- **Breaks per day:** at most `family_settings.break_max_per_day`, default **6**.

### Rules

1. **Starting a break.** `break.canStart` is true when all of these hold:
   - bank ≥ **5** minutes;
   - breaks taken today < max;
   - free time has not started;
   - the laptop is in a locked study status (LOCK_P1 / LOCK_P2 / FREE_READY; not a parent lock, not trust or sick, not a parent open);
   - no timed run (required or extra) is running.

   **The old "a part must be done" condition is removed** (parent decision 08/11).
2. **Length.** Starting a break uses the **whole bank**: `planned = bank`. BREAK is open until `started_at + planned`, clipped at 00:00, or until a parent LOCK override is created (09/11). A homework run may keep running during a break; its time during the break is not focus.
3. **"Học tiếp" early.** `ended_at = now`. Used = floor((ended − started) ÷ 1 min), with a minimum of 0. The rest stays in the bank, and a new block starts from that break's **start**. Starting a break always resets the block, whether it ends early or runs to the end.
4. **Free time.** When both parts are done, free time starts as today (rules 8 and 15 are unchanged). Its length = `free_minutes` + **the bank at `free_started_at`**, and it is still clipped at 00:00.
   - The bank includes the current block's earnings.
   - It is computed from data at `free_started_at`, so every read gives the same answer.
   - A running break at that moment ends (rule 8 is unchanged). The unused part of that break is in the bank, so it is added to free time.
5. **Legacy.** A day whose `day_sessions` row has the legacy `break_started_at` (or `break_skipped`) and no `day_breaks` rows counts as one break of `break_minutes` that started then. This is only for days in flight when R8b is deployed. `break_minutes` stays as a legacy column and no longer drives anything else.
6. **Status priority (DESIGN §5)** is unchanged. BREAK stays where it is, and FREE stays above BREAK.
7. **Everything uses the server clock and is clipped at 00:00. Malformed data throws** (fail-closed).

### Data (migration `0014_break_bank.sql`)

- **New table `day_breaks`** with columns:
  - `id` uuid pk
  - `family_id` uuid, FK to families
  - `child_id` uuid, FK to profiles
  - `local_date` date
  - `started_at` timestamptz not null
  - `planned_minutes` int not null, check > 0
  - `ended_at` timestamptz null
  - `created_at`

  It needs an index on (child_id, local_date). Enable RLS with a select policy for family members (same pattern as `task_runs`) and **no insert / update / delete policy for children**; the server routes use the service role. Grant select to authenticated and grant everything to service_role, as other tables do.
- **New `family_settings` columns:**
  - `break_tiers jsonb not null default '[[45,10],[90,30],[120,45],[180,60]]'`, with a check that it is an array;
  - `break_max_per_day int not null default 6`, with a check between 0 and 12;
  - `break_run_cap_minutes int not null default 180`, with a check between 30 and 600 (09/11).
- **Do not drop** `break_minutes` or the `day_sessions.break_*` columns.
- Add an RLS test to `supabase/tests/`. Run `bash scripts/test-db.sh`:
